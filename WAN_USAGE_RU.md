# Wan на RunPod: выбранная схема

## Что установлено

На Network Volume используется один согласованный комплект без платных API:

- Wan2.2 VACE Fun A14B FP8, high-noise + low-noise — Image/Reference/Control → Video;
- Wan2.2 Fun InP A14B FP8, high-noise + low-noise — Start Frame и Start + End Frame;
- общий UMT5 XXL FP8, Wan VAE и CLIP Vision H.

Полный объём комплекта: 71 535 540 859 байт, примерно 66,6 GiB. Turbo/Lightning LoRA не устанавливаются: обе стадии диффузии выполняются полностью ради качества.

## Почему именно этот комплект

Wan2.2 Animate-2 новее по дате, но это специализированная модель переноса движения: ей обязательно нужны reference character и driving video. Она не заменяет обычный Image → Video.

Wan 2.6/2.7 Reference-to-Video с настоящим переключателем `multi-shot` доступен в ComfyUI как облачный API-вызов. Открытых весов для локального запуска этого режима нет, поэтому он исключён.

VACE Fun закрывает изображения, субъектные референсы и управляющее видео/маску; Fun InP закрывает первый и последний кадры. Вместе это наиболее полный бесплатный набор, который помещается в оставшиеся 80 GiB и рассчитан на выбранную GPU с 48 GB VRAM.

## Как запускать

### Обычное Image → Video

Использовать Fun InP:

1. загрузить стартовое изображение;
2. end image оставить пустым;
3. выбрать обе модели Fun InP: high-noise и low-noise;
4. задать prompt, размер и число кадров;
5. выполнить обе стадии без Lightning LoRA.

### Первый + последний кадр

Использовать тот же Fun InP workflow, передав start image и end image. Это основной режим для контролируемого перехода между двумя кадрами.

### Reference → Video

Использовать VACE Fun:

1. основное изображение/кадр передать как стартовый вход;
2. reference image передать в reference-вход VACE;
3. при необходимости передать control video или маску;
4. выбрать VACE high-noise и low-noise;
5. использовать одинаковые референсы во всех связанных сценах.

Несколько изображений-референсов подаются как IMAGE batch, если выбранный graph это поддерживает. Перед production-рендером нужно проверить, что все изображения действительно попали в batch, а не только первое.

### Мультишот без API

Один локальный вызов Wan2.2 не создаёт честный multi-shot. Правильная бесплатная схема — очередь отдельных шотов:

1. каждый шот генерировать отдельным job;
2. во всех job использовать один набор reference images и одинаковое описание персонажей;
3. последний кадр шота N использовать как start frame шота N+1;
4. если известен следующий ключевой кадр, передавать его как end frame;
5. после генерации объединить MP4 без повторного кодирования, если параметры совпадают.

Так можно повторять неудачный шот отдельно и не терять уже готовые сцены.

## Рекомендуемые настройки

- Черновая проверка движения: 480×864, 81 кадр, 16 fps (около 5 секунд).
- Финал 9:16: 720×1280, 81 кадр, 16 fps; это значительно медленнее.
- Seed фиксировать для сравнительных тестов, но менять при поиске удачного движения.
- High-noise и low-noise должны использовать одну пару моделей одного семейства.
- Не подключать Turbo/Lightning при финальном качестве.

## Где будет результат

Handler остаётся прежним: ComfyUI API workflow приходит в существующую RunPod queue, MP4 сохраняется в `runpod-results`, после чего возвращается тем же механизмом, который раньше использовал MiniMax. Telegram-бот потребуется отдельно переключить с H3 workflow на Wan workflow; до этого его старые H3-команды работать не будут.
